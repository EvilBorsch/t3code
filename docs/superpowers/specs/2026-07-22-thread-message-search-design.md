# Поиск тредов по содержимому сообщений

## Цель

Расширить поиск тредов в палитре команд: сохранять существующие совпадения по заголовку, проекту и ветке и дополнительно показывать активные треды, в сообщениях которых встречается введённый текст.

## Архитектура

Оболочки тредов намеренно не содержат сообщения, поэтому клиент не должен загружать детали всех диалогов. Сервер хранит отдельный FTS5-индекс `projection_thread_messages_search` с триграммным токенизатором и поддерживает его SQLite-триггерами при вставке, изменении и удалении строк `projection_thread_messages`.

Новый типизированный unary RPC `orchestration.searchThreads` принимает нормализованный запрос длиной от 3 до 256 символов и предел выдачи до 200 тредов. Репозиторий сообщений ищет совпадения в FTS-индексе, соединяет их с активными `projection_threads`, исключает удалённые и архивные треды и возвращает уникальные идентификаторы.

Веб-клиент после короткого debounce параллельно запрашивает все подключённые окружения. Полученные scoped-идентификаторы добавляют текущий запрос как самый слабый поисковый термин соответствующего элемента палитры. Поэтому при одинаковом запросе совпадения по заголовку, проекту и ветке остаются выше совпадений только по сообщению.

## Поведение и ошибки

- Пустой запрос и запрос короче трёх символов не вызывают серверный поиск; существующий локальный поиск продолжает работать без изменений.
- Поиск по сообщениям регистронезависим, включая Unicode, благодаря FTS5 `trigram`.
- Архивные и удалённые треды не появляются в результатах.
- Ошибка одного окружения не блокирует локальные результаты и результаты остальных окружений.
- Смена запроса не применяет устаревшие асинхронные совпадения к новому тексту.

## Проверка

- Миграционный тест проверяет создание и наполнение FTS-индекса для уже существующих сообщений.
- Тест репозитория проверяет Unicode-регистр, обновление и удаление индекса, а также исключение архивных тредов.
- Тест логики палитры проверяет появление треда по совпадению в сообщении и приоритет заголовка над содержимым.
- Целевые тесты, форматирование, линтер и проверки типов выполняются для затронутых пакетов.
- В изолированном окружении T3 создаётся тестовый тред, после чего палитра команд проверяется через контролируемый браузер.

## Ограничения процесса

Работа выполняется локально. Коммиты, ветки, worktree, push и другие операции с `origin` запрещены проектными инструкциями.
